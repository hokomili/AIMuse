# Security policy

AIMuse is pre-release software. Do not use this alpha as the sole copy of important recordings or grant it broad autonomous filesystem, recording, plug-in, MIDI, or audio-device authority.

## Security boundaries

- The Electron renderer is sandboxed with context isolation, no Node integration, a narrow frozen preload API, navigation/window denial, CSP, ASAR integrity enforcement, and hardened Electron fuses.
- MCP listens only on loopback and every HTTP path, including health, requires authentication. Each engine start creates a fresh random 32-byte bearer; stopping the listener discards it. Empty or malformed authority never compares equal, and stop synchronously closes admission before pending session cleanup, so the still-closing socket rejects health, MCP methods and unknown routes without exposing engine identity. The bearer is never exposed through renderer/preload IPC or written into durable client setup, and AIMuse does not recover it through macOS Keychain, Windows DPAPI, Linux secret storage, Electron `safeStorage`, or another protected-secret backend.
- GUI and headless startup atomically publish the current bearer only as PID/instance/profile-bound ephemeral run-state below a dedicated AIMuse-owned private directory. POSIX uses owner-only `0700`/`0600`; Windows uses a protected ACL limited to the launching user, SYSTEM and Administrators. The stdio bridge validates file identity, process liveness and authenticated health before use. Clean stop removes only the exact matching record; dead-PID crash residue may be replaced but cannot authenticate, while a still-live PID whose engine identity is not verifiable blocks replacement as ambiguous.
- One-time client snippets contain only the AIMuse executable, `--mcp-bridge`, and a stable target-profile path. They contain no Chromium `--user-data-dir`, bearer, URL, PID, instance ID, account credential, or per-launch value. Before `app.setPath`, the entry derives and creates only a deterministic sibling directory, requires every component to be real/link-free, and rejects canonical-path or filesystem-identity equivalence with the target, including Windows case/reparse/junction aliases; it revalidates both objects immediately afterward. macOS activation is prohibited before validation, and a malformed or aliased entry exits without installing either profile. AIMuse never edits an agent client's configuration file. A relocated ad-hoc arm64 package passed headless process evidence for an exact installed bridge with no renderer; Electron's observed GPU/utility helpers used only the isolated sibling profile, never the target. Static-client restart recovery and zero-survivor checks also passed. Visual no-Dock/UI, GUI, Windows and distribution acceptance remain explicit gates. The full-token connection export remains formal owner-private QA coordination only, not product onboarding.
- Autonomous access is deny-by-default and limited by a process-lifetime `AuthorityPolicy`: canonical file roots and overwrite paths, plug-in allowlist, maximum runtime, and separate microphone/MIDI permissions.
- Media bytes enter through controlled import, recording contracts, or deterministic render jobs. Project operations do not accept inline bytes or invoke external content providers.
- AIMuse contains no provider adapter, provider credential API/store, generation job/tool/UI, or paid-service request path. Legacy generation-provenance fields remain only so previously authored project files can be validated and reopened; live transactions and whole-project snapshot installs cannot mutate that map or its historical generation-source assets, and the data confers no executable provider capability.
- Project extraction rejects absolute/traversal paths, excessive entry counts, excessive total size, and unsafe compression ratios.
- Ordinary application data and the remembered MCP port remain non-secret. Package policy disables Electron cookie encryption because the installed application has no persistent secret requiring an operating-system secret store.
- Local macOS QA packages are development artifacts. Only reviewed identity-signed, notarized, stapled bytes are eligible for distribution review; no such release claim is made by this alpha checkpoint.
- Root-local MCP connection, coordinator, profile, and retained QA evidence is never source. The initial Git snapshot must use the allowlist in `docs/INITIAL_COMMIT.md`, never a repository-root wildcard.
- Third-party plug-ins are intended to run outside the canonical engine process. The current alpha does not yet provide production SDK-backed hosting; do not interpret its process shells as a completed sandbox.

Use narrow read/write roots, an empty overwrite list, no microphone/MIDI permission unless required, and an explicit plug-in allowlist. Stop the engine when an autonomous session is complete.

Report a suspected vulnerability privately to the repository owner with the affected build, reproduction steps, and impact. Do not include bearer tokens, private audio, or project archives in a public report.

## Known alpha audit status

As of 2026-08-04, `npm audit --omit=dev` reported zero high or critical production findings and two moderate entries. Both traced to `@modelcontextprotocol/node@2.0.0` depending on `@hono/node-server@^1.19.9`, whose separately exported `serve-static` middleware had a Windows encoded-backslash traversal advisory. AIMuse imports only the adapter's root `getRequestListener` path and does not register `serve-static`, but the dependency remains present. Re-run the pinned release audits for the exact candidate; this historical result is not a current release certificate.
