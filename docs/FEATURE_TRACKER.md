# AIMuse feature tracker

Last audited: 2026-08-13

This is the source of truth for implementation status. The README and architecture documents describe the intended v1 product; an item is not complete merely because its type, dependency pin, button, process shell, or protocol message exists.

## Status rules

| Status | Meaning |
| --- | --- |
| ✅ Verified | The workflow is implemented and covered by an automated acceptance, contract, regression, golden, or fault-injection test. |
| 🟢 Working | The workflow is usable in the current editor or engine, but its acceptance coverage is incomplete. |
| 🟡 Partial | A useful subset works, but a material part of the promised workflow, integration, or fidelity is absent. |
| 🟠 Scaffolded | The model, UI, dependency, or process boundary exists, but the workflow is too thin to call usable. |
| ⬜ Missing | No meaningful implementation exists yet. |
| ⏸ Deferred | Explicitly outside the selected v1 scope. |

Priorities are `P0` release blocker, `P1` core v1 workflow, `P2` completeness/fidelity, and `P3` polish. A feature may move to **Verified** only when its exit criterion has automated evidence. A regression that invalidates the evidence moves the item back immediately.

### Literal release-candidate bar and ranked remaining-gap audit (2026-08-13)

AIMuse may be described as a release candidate only after one committed, reviewable Node 24 baseline is frozen as an immutable checksummed release subject and a fresh independent Level 3 run passes the complete selected-v1 acceptance matrix. That matrix includes clean Windows 11 x64 install/portable lifecycle, licenses/SBOM/advisory/native-SDK/signing posture, exhaustive authenticated MCP and native Computer Use in both directions, audio/recording/MIDI/PDC/DSP/stretch, SDK-backed VST3/CLAP, codecs/interchange/providers, corruption/recovery/security/performance/accessibility, and exact report/manifest/tracker/limitation agreement. No Blocker/P0 may remain open; any P1 exception must be explicitly accepted and linked. The current `0.1.0-alpha.0` tree does not meet that bar, and focused source-level or prior immutable package evidence must not be promoted into an RC claim.

Ranked remaining gaps are:

1. **Product P0 implementation:** physical MIDI and audio/MIDI recording (`AUD-03`–`AUD-05`), delay compensation (`AUD-08`), production time stretch (`AUD-11`), remaining live graph/DSP/device behavior, and SDK-backed plug-in hosting are absent or incomplete. These require native-helper/audio/device work and cannot be closed by a pure-headless MCP slice.
2. **Formal RC evidence:** a fresh immutable Level 3 subject, clean Windows installer/portable lifecycle, exhaustive native UI/MCP/audio/hardware/performance/accessibility evidence, signing posture, SBOM/licenses/advisory disposition, and exact artifact/report agreement remain unearned. They require separate packaging, hardware, Computer Use, signing/release, or independent-test authority.
3. **Pure-headless agent release gates:** AGT-18 covers project transactions, actor history, checkpoint/variant work, generation, direct plug-in device edits, WAV media analysis, audition/consolidation render-job creation, running render late effects, and a repeated deterministic mixed-family fair-scheduler soak. Approved single-path project-open, project-save, compound project-unpack, plug-in-instantiate and sequential media-import producers separately have terminal cancellation with literal waiting/running/returned/rejected effects; unpack preserves sequential archive output plus later open effects, import keeps per-file cache/transaction/warning partial success, and instantiate remains outside fair admission as one atomic catalog-descriptor device rather than a native instance. Recording and other generic approved continuations, session ownership, packaged repetition and the remaining producer-specific domain-action/cancellation matrix remain. Media listing plus plug-in catalog/scan keep observation or catalog-job contracts rather than being misclassified as project mutations.
4. **Breadth and compatibility:** the remaining QA-01 corruption/integrity matrix, compressed codecs, DAWproject fidelity and accessibility/input coverage remain before final v1 closure. Dependency advisories are currently clear, but must be revalidated against a fresh registry during formal release evidence rather than treated as permanently disposed.
