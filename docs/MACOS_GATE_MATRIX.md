# macOS acceptance gate matrix

This is the literal macOS acceptance contract for AIMuse. Local development evidence is exact-subject and exact-architecture; it does not inherit Windows/WASAPI certification and it is not a distributable macOS release certificate.

Status vocabulary is intentionally strict:

- **LOCAL PASS** — exercised successfully on this Darwin host with the command and subject named below.
- **PARTIAL** — a meaningful bounded subset passed, but the full gate did not.
- **PRODUCT-WIDE UNIMPLEMENTED** — the capability is absent on Windows and macOS; it is not a Mac regression and cannot be claimed as parity.
- **EXTERNAL REQUIRED (HARDWARE/CREDENTIAL)** — exit requires physical hardware events, release credentials or another external facility that this task did not use.
- **FORMAL CERTIFICATION UNEARNED** — implementation-task evidence may exist and an independent attempt may have run, but the required fresh independent workflow has not completed all mandatory gates.

## Formal independent workflow

Before a formal run, create a new protected `test-results/luna-high/<run>` root for preflight/log/subject manifest/report and a disjoint `test-results/playwright/<run>` output. Set `AIMUSE_FORMAL_RUN_ROOT`, `AIMUSE_PLAYWRIGHT_E2E_OUTPUT_DIR` and optionally `AIMUSE_PACKAGE_SUBJECT_MANIFEST=<formal-root>/package-subject.json`; preserve the real automation exit with shell `pipefail` plus `tee <formal-root>/automation.log`. Preflight records source/branch/index/dirty inputs only. The automated command packages exactly once and only then declares the immutable subject; reverify the returned manifest digest at coordinator handoff and after cleanup. Never call a second package command over those bytes.

The tester must own sandboxed `qa-session status`; the coordinator may not replace it with an unsandboxed status call. The ordinary path is `processInspection: "performed"`, supported true, denied false, status `"alive"` and `processAlive: true`; `ESRCH`, absent or identity mismatch blocks even if an endpoint responds. Only sandbox `EPERM` may use the alternate path: inspection denied, supported false, status `"permission-denied"`, alive null, `packageSubjectVerified: true`, unchanged manifest/subject/executable, exact connection/session/health PID-instance-profile-URL, verified authenticated MCP HTTP-400 `initialization_required`, and `inspectionFallbackVerified: true`. Unsupported inspection, missing health/authentication or any mismatch blocks before Computer Use or MCP.
